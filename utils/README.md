# Utils

Miscellaneous skills that live in this repo but are **not part of the Giant Brains suite**. The top-level skills form a curated arc (decide well, then improve verifiably); everything here is standalone tooling -- harness configuration, workflow conveniences, one-off helpers -- with no claim to that narrative.

Each skill subfolder is a normal skill (a directory containing `SKILL.md`) and installs the same way: symlink or copy it into `~/.claude/skills/`. Subfolders without a `SKILL.md` are docs or kits, not skills -- the skills sync ignores them.

## Skills

- **frontdoor** -- The `front-door` skill: walk a repo's front door as a brand-new user and report whether they can actually get from clone to working -- not just whether the docs exist. Covers competing/duplicate onboarding docs, install-script red flags, auth/access gates, first-run success, doc-vs-code drift, and accidentally committed secrets (in the tree or git history), classifying each friction point as agent-soluble vs human-gated. Can also save the audit as a persistent `FRONTDOOR.md` dashboard at the repo root -- a re-runnable health board where every finding carries a deterministic check (empty output = all green) -- and refresh it in place on later runs (OPEN -> FIXED). See [frontdoor/FRONTDOOR.md](frontdoor/FRONTDOOR.md) for a worked example (this repo's own board).
- **obsidian-habit** -- Run the daily Obsidian habit-building exercise as a 6-state FSM that surfaces exactly one low-friction tactic per day (front-door homepage, frictionless capture, auto-archive stale notes, rebalance-OS RAG morning pull, visible streak, then daily maintenance) so vault overwhelm stops blocking the habit -- the FSM already picked the plan, so the only thing the user decides each day is *adopt / decline / defer*. `scripts/habit.py` is the single writer of `<vault>/_meta/obsidian-habit/state.json` (atomic write-tmp-then-rename) and appends every run to an append-only `events.jsonl`; `archive_stale_notes.py` is dry-run by default, bounded to 500 files/run, and writes a reversible manifest on `--apply` (with `--undo`); `streak_update.py` marks the visible streak. Manual-only tactics (plugin installs, OS shortcuts, cron wiring) live in [obsidian-habit/references/tactics.md](obsidian-habit/references/tactics.md). Needs `OBSIDIAN_VAULT_PATH` (or `--vault`) and `python3`; the RAG pull degrades to a manual step if rebalance-OS is unreachable.
- **read-only** -- Add a curated set of read-only permission rules (file reads, directory listings, grep/glob search, git inspection, system/environment checks) to a Claude Code `settings.json` allowlist, so safe reads stop triggering permission prompts. Uses exact-match rules where flags can mutate (`git branch -d`, `find -delete`) and excludes trivially write-capable commands (`echo`, `sed`, `tee`, `xargs`).
- **rpr** (Reduce Permissions Requests) -- React to the few commands that *just* prompted this session and turn them into narrow allowlist rules appended to the git-ignored `.claude/settings.local.json`. `scan.py` reads the current project's transcript, drops calls already covered by an allow rule, and grades the rest: safe commands get a prefix wildcard (`Bash(git status:*)`), genuinely destructive ones (`rm`, `sudo`, `pip install`) get an *exact-match* rule, and env-var pipelines get a wrapper-script recommendation instead of a rule that can't silence the prompt. `write_rules.py` does the idempotent merge from a rules file (no shell-escaping hazard). Differs from **read-only** (a static safe-read preset) and from history-mining `fewer-permission-prompts` by reacting only to the recent, specific prompts. Self-tested under `tests/` (`python3 tests/run_tests.py`).
- **shakedown** (v1.0) -- Test and harden any other script-calling skill against CWD-sensitive path-discovery bugs (the `.sh` that runs in one session but comes back "not found" in another). Ships a static path audit (`scripts/audit.sh` over the shared `scripts/lib.sh` core) and a live harness (`scripts/harness.sh`) that runs the documented command across a foreign-CWD / nested / spaces-in-path / project-vs-user-install / stripped-exec-bit matrix, then re-runs a `{SKILL}`-anchored fix to prove it survives. Read-only against the target; writes only a graded report under `SHAKEDOWN/` (proposing a patch, not applying it). ASCII output, bash-3.2 compatible, dogfooded. See [shakedown/IMPROVEMENTS.md](shakedown/IMPROVEMENTS.md) for build status.
- **swe-diagram** -- **Moved out of this repo.** It now lives in [xyz-3-agents-swarm](https://github.com/Claude-AI-Tools-Ventura-County/xyz-3-agents-swarm) and is maintained there; this repo is no longer its source. Listed here only so anyone following an old link knows where it went. (Migrated in `51a7c40`.)
- **vscode-color** -- Give each git repo a stable, distinct VS Code background tint so two windows are never confused. `vscode-color.py` merges a seven-surface palette (editor, sidebar, activity bar, panel, active tab, title bar, status bar) into the repo's `.vscode/settings.json` under `workbench.colorCustomizations`, preserving other keys, so it applies every session with no per-session step. Two modes: **deterministic** (SHA-256 of the repo's GitHub slug -> a hue; same repo always the same color, un-pushed repos fall back to a `local/<folder>` slug) and **manual override** (the user names a color or feel -> explicit HSL knobs). Dark-theme tuned with a `--light` variant; `--print` previews slug + hex before writing. A manual tint stamps a `"// vscode-repo-tint": "manual"` marker and deterministic mode then refuses to clobber it without `--force`. Adapted from the maintainer's `~/bin/vscode-repo-color`, adding the marker, the clobber guard, and JSONC-tolerant merging.

## Docs & kits

- **claude-code-dotfiles-fork** -- Standalone kit for syncing `~/.claude` across machines via a private git repo and Claude Code SessionStart/SessionEnd hooks, with optional propagation of a skills repo as real files. Self-contained: [INSTALL.md](claude-code-dotfiles-fork/INSTALL.md) is the machine-agnostic setup guide, [templates/](claude-code-dotfiles-fork/templates/) holds the allowlist `.gitignore`, the three hook scripts, and the settings hooks snippet, [HANDOFF.md](claude-code-dotfiles-fork/HANDOFF.md) documents the maintainer's live deployment, and [README.md](claude-code-dotfiles-fork/README.md) is the upstream project's original documentation (MIT-0 fork of `elizabethfuentes12/claude-code-dotfiles`).
- **skill-sync** -- Standalone kit for keeping one logical file in sync across two repos on the same machine, bidirectionally and last-write-wins. `skill-sync.sh` reads tab-separated file pairs from `skill-sync.conf`, compares content hashes *first* (so git's mtime resets can't clobber the newer edit), and only then lets the newer `mtime` win -- copying atomically and logging each action; supports `--dry-run`. Currently pairs `swe/SKILL.md` between this repo and the `xyz-3-agents-swarm` repo. [skill-sync-plan.md](skill-sync/skill-sync-plan.md) documents the design and the mtime catch.
